# Languages (i18n)

English is the site's source language and lives at the root with every URL it has always had. Japanese, Spanish,
French, German and Italian live under `/ja`, `/es`, `/fr`, `/de`, `/it`, with the same English slugs inside
(`/es/pokemon/charizard`). A language is served only when it is in `LIVE_LOCALES` (comma list, read at build time) and
only for pages listed for it in `src/i18n/routes.ts` (`TRANSLATED`); everything else under a code is a 404.
`LIVE_LOCALES` empty (today's production) builds exactly the English site: no language routes, no language code in the
browser (see "English-only builds" below).

## Text in code: namespaces

Every piece of visible text comes from a message namespace:

- `src/messages/en/<name>.json` — the English text (ICU MessageFormat: `{name}`, `{n, plural, one {# win} other {# wins}}`,
  `{x, select, a {…} other {…}}`, `<b>tags</b>`).
- `src/messages/<locale>/<name>.json` — the same keys in each language (`npm run lint` checks keys, ICU and
  arguments; Japanese may drop plural forms).
- `src/messages/<name>.ts` — `export default defineNamespace("<name>", en)`.
- Add the name to `src/i18n/namespaces.ts`.

Keys are typed: `t("missing.key")` fails `tsc`.

### Server components

```tsx
import { serverT } from "@/i18n/server";
import ns from "@/messages/ns";

export function Thing() {
  const t = serverT(ns);          // synchronous: never make a component async for text
  return <h2>{t("title")}</h2>;
}
```

`generateMetadata` uses `serverT` too (pages that had `export const metadata = …` become
`export function generateMetadata(): Metadata`).

### Client components

```tsx
"use client";
import { useT } from "@/i18n/client";
import ns from "@/messages/ns";

const t = useT(ns);
```

A page whose client components use a namespace wraps them so a page in another language sends that language's text
along (it renders nothing extra on English pages):

```tsx
<ClientMessages namespaces={[ns]}>
  <ClientThing />
</ClientMessages>
```

The header, footer and tab bar namespaces are already provided by the language layout (`CHROME_NAMESPACES`).

### Rich text

`t.rich("key", { b: (chunks) => <strong>{chunks}</strong> })` for messages with `<b>…</b>`.

### Keeping English exactly as it was

- The English JSON holds the exact text the JSX showed: JSX collapses a line break and indentation into one space.
- `#` in a plural formats with grouping ("1,234"); where the old code printed `${n}` (no grouping), write `{n}`.
- Keep text order and markup the same; `scripts/i18n/compare-html.mjs` compares every prerendered page with main.
- Lists: `listNames` stays for English; other languages use `Intl.ListFormat` (see `localStreakText`).
- Numbers: `formatNumber(n, locale)` (en-US for English, as before).

### Links

`@/components/ui/Link`, `@/components/ui/PlainLink`, `@/components/ui/Anchor` and `@/i18n/navigation`'s `useRouter` /
`usePathname` keep a page in its language (ESLint enforces it). `usePathname()` gives the English path.

## Translation style

- Spanish (Spain): tú. French: tu. German: du. Italian: tu. Japanese: です・ます, game-text style where the games
  use it.
- Pokémon, moves, abilities, items, types, natures, regions and games use the official names of each language
  (`src/data/i18n/<locale>/*.json`, from PokéAPI; species in `src/data/species-names.json`).
- Brand names never change: PokéIQ, Pokédle, PokéGuessr, Pikadoku, PokéConnections. The nav's short game labels
  (Wordle, Connections, Sudoku, Guessr) stay as they are in every language.
- The same site rules apply in every language: no "N things" counts in copy, no invented data, never the word
  "Olympic", and PokéGuessr never names (or hints at) a place before the reveal.
- Titles, H1s and descriptions use the terms people search for in that language.

## English-only builds

With `LIVE_LOCALES` empty, next.config swaps a few modules for `.english` twins (`RootChrome`, `Anchor`, `Lazy`,
`i18n/navigation`, `i18n/paths`, `i18n/catalog`, `i18n/client`) and rewrites `@/components/ui/PlainLink` to
`next/link`, and English messages compile to plain strings and small functions (`scripts/i18n/icu-loader.cjs`), so
the browser gets no formatter and no language code. Tests keep each twin's exports equal to its module's.

## Checks

- `npm run lint` — ESLint, the generated `[locale]` mirror (`npm run i18n:mirror`) and the message check.
- `npx vitest run tests/i18n-foundation.test.ts tests/i18n-messages.test.ts`
- After `next build`: `node scripts/i18n/route-types.mjs --check`, `node scripts/i18n/bundle-sizes.mjs`,
  `node scripts/i18n/compare-html.mjs <main's .next/server/app> .next/server/app`.
- With a language live (`LIVE_LOCALES=es I18N_PREVIEW=1 npm run build && npm start`):
  `LIVE_LOCALES=es node scripts/e2e-i18n.mjs http://localhost:3000` (canonical, hreflang, sitemaps, picker, and no
  English left on translated pages).
